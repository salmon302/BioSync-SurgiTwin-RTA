# sim/segmentation

Segmentation pipeline for FR-MS-001 (SRS.md): DICOM volume ingest and segment export on the native Windows 3D Slicer install (SOUP pin in sim/SOUP.md).

Status: plan task 2.1, slice 1. The pipeline runs end to end on a smoke dataset. The output is not G2.1 reference data.

## Pinned environment

- 3D Slicer 5.12.4, revision 4e21c19, installed at `I:\Library\3D Slicer 5.12.4` (the path in sim/SOUP.md; the path `C:\Users\salmo\AppData\Local\NA-MIC\Slicer 5.12.4` does not exist on this host)
- Slicer bundles SimpleITK 2.5.5 and VTK, used through Slicer's Python. No additional packages are installed. Both are recorded in the output manifest.

## One-command run

From the repository root:

    powershell -ExecutionPolicy Bypass -File sim\segmentation\run.ps1

The runner starts `Slicer.exe --no-splash --no-main-window --python-script sim\segmentation\segment_reference.py` with stdout and stderr captured to `SNDEV\logs\segment-run-<dataset-id>-<UTC timestamp>.log`. It waits for the `SlicerApp-real` process to exit and prints the wall time. It exits non-zero unless the log contains `SURGITWIN_DONE`.

Run inputs are set in `run.ps1`: dataset ID, series UID, and data folder. The script reads them from environment variables.

## Pipeline

1. `DICOMUtils.importDicom` imports the DICOM folder into a temporary Slicer database. `loadPatientByUID` loads the series. The script picks the acquisition with the most slices and records the others as excluded.
2. A segmentation node is created with the selected volume as reference geometry.
3. Three segments are created:
   - `parenchyma_liver_smoke`: Segment Editor Threshold, 40 to 200 HU, then a numpy ROI clip to a liver box, then SimpleITK median smoothing (3 mm kernel) and keep-largest-island.
   - `lesion_synthetic`: a sphere of 10 mm radius at the centroid of the organ mask, clipped to the organ mask. This is synthetic and not a clinical lesion.
   - `vascular_keepout_contrast`: Segment Editor Threshold, 150 to 300 HU, numpy ROI clip to the aorta and IVC box above the vertebral body, then SimpleITK dilation by 2 mm.
4. Each segment is exported as a labelmap NRRD and a binary STL. The STL is built with `vtkDiscreteMarchingCubes` on the exported labelmap, transformed to RAS with the node matrix.
5. A provenance JSON is written beside each segment, and `manifest.json` lists all files with SHA-256 hashes, voxel counts, and bounding boxes.

Outputs go to `sim/segmentation/output/<dataset-id>/`.

## Provenance rules

- Every dataset in `data/` has a checksum and source entry in `data/PROVENANCE.md`. New datasets require the same entry before a run.
- Each per-segment sidecar records: dataset ID, source note, volume UID (series instance UID), volume node name, shape, spacing, excluded acquisitions, the operator (script name and SHA-256), Slicer version and revision, the effect chain with parameters and library versions, output file names, mesh method, triangle count, voxel count, timestamp (UTC), and `is_g21_reference`.
- Manifests carry `is_g21_reference: false` until a dataset with reference labels is run under slice 2.
- Outputs are regenerated by the runner. Old outputs are overwritten by the same names, so keep the run log as the audit record.

## Known limitations (slice 1)

- The organ ROI and vessel ROI are fixed boxes, chosen from one mid-axial slice. They are not anatomical atlases.
- The vessel segment includes part of the vertebral body top at HU 150 to 300. Bone exclusion is not implemented.
- The Segment Editor Smoothing and Islands effects crashed `SlicerApp-real` in a no-main-window run (exit abnormally, seen 2026-11-05). The morphology steps run through SimpleITK instead. The Segment Editor Threshold effect runs normally.
- The Threshold effect is a Segment Editor scripted effect. The ROI clip and the lesion sphere are numpy steps. Each step is listed in the sidecar.
- The organ mesh is about 63 MB of binary STL at 0.78 by 0.78 by 5 mm voxels.

## Slice 2 plan

- Reference labels: obtain expert labels for the liver, tumor, and vessel classes on the same DICOM series. The TCIA SEG object in `data/` is a candidate, but the labels must be kept separate from the pipeline inputs to avoid self-comparison.
- Evaluation: compute Dice per segment between pipeline labelmaps and reference labels with the same geometry, recorded in a dedicated evaluation log. The G2.1 threshold is Dice 0.90 or higher.
- Dataset: decide whether the Kitware TAIR set (CTA, NIfTI, CC BY 4.0, annotations expected December 2026) is used for G2.1, or a DICOM liver set with reference labels. This is an open decision for the user.
- Bone exclusion for the vascular segment and a documented anatomical ROI method.
- Replace the crashing Segment Editor effects with the scripted path if a headless-safe configuration is found.
